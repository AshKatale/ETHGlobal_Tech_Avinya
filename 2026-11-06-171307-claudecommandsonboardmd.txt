  # AgentForge briefing (as of 2026-11-06, the date in
  `docs/agent_forge_PRD.md`; no doc carries a newer date)

  ## 1. What it is
  AgentForge is a marketplace where AI agents are listed, hired and paid
  on-chain (`docs/agent_forge_PRD.md`, Executive Summary). The users are clients
  (human or agent), agent listers, and autonomous agent clients. The MVP is a
  solo build for ETHGlobal Mumbai. The one-job demo is the golden path in
  `docs/build_plan.md`, ending in a HashScan link and a chainscan link on
  screen.

  ## 2. How it works
  Golden path (`docs/build_plan.md`, never cut):
  1. Sign in.
  2. Request.
  3. Quote.
  4. Sign terms.
  5. Fund `EscrowVault` with Hedera USDC.
  6. Agent submits.
  7. 0G-generated tests run.
  8. Two verifier signatures.
  9. Verdict recorded on 0G.
  10. Vault releases USDC.
  11. HashScan and chainscan links appear.

  Which chain holds what:
  - **Hedera testnet:** `EscrowVault` and USDC (token `0.0.429274`). Also x402
  payments, including the agent-to-agent spend (`static-auditor` sells a call
  and `solidity-builder` buys it).
  - **0G Galileo (chain ID 16602):** `AgreementRegistry` (agreement, submission,
  verdict and settlement records), evidence packs in 0G Storage, and
  test-generation inference via the 0G Compute Router.
  - **Our servers:**
    - Postgres 16 holds app state and the `chain_outbox`.
    - `apps/api` contains the indexer and sandbox launcher.
    - Verifier A, Verifier B and the relayer are separate processes with
  separate keys.
    - A Docker runner executes `forge test`, `slither` and `gitleaks`.

  ## 3. Stack and repo layout
  Stack (`CLAUDE.md`): TypeScript (Node 22), Solidity 0.8.24, pnpm + Turborepo,
  Next.js, Fastify + Zod, PostgreSQL 16 + Drizzle, Foundry, viem, `@x402/*`,
  `@0gfoundation/0g-storage-ts-sdk`.

  Phase 1 steps 1.1–1.13 are written:
  - Foundation:
    - Fastify + Zod server, with the money helper (HBAR in tinybar as bigint,
      toRpcValue() for weibar).

    - The database connects to Neon with pg; there's no local Postgres.
  - Login and marketplace: Wallet login and sessions work through a nonce signed
    in the wallet. Agents, requests, quotes and agreements are in. Accepting a
    quote creates the agreement.
  - Onboarding:
    - Public GitHub repo fetch (capped at about 100 KB).
    - Custom code checks and the NVIDIA call, which returns validated JSON.
    - Benchmark scoring: 40% custom checks plus 60% AI, with an 80/100 pass
      mark.
    - A pass lists the agent; a score below 80 keeps it unlisted.
    - A GitHub or NVIDIA failure is recorded as an error, never as a failed
      benchmark.
    - The report goes to 0G Storage; if 0G is down it stays in Postgres.
  - Verification: When an agent submits, verification starts in the background.
    NVIDIA turns the requirement into a checklist and judges the work against
    it. Custom code runs the checks the client ticked. An NVIDIA failure gives
    an ERROR result with a retry, never a FAIL.
  - Agent-to-agent calls: The 30% budget rule (bigint math), a depth limit of 2,
    and recorded blocked calls are in.

  - Chain steps (escrow creation, release, refund, the real agent-to-agent
    payment) wait for Phase 3.
  - The agreement's funded, released and refunded states come from two dev-only

  - Verdicts are stored without a signature for now.

  Description
  ## Summary
  Adds the blockchain layer. A client's HBAR is locked in a per-job escrow
  contract on Hedera testnet. It is released or refunded based on a

  **Contracts (`contracts/`, Foundry, Solidity 0.8.24)**

  - Verdicts and delegations are EIP-712 messages signed by the platform

❯ give me foundry commands to run in the powershell
⏺ These work in PowerShell from the repo's contracts folder. I wrote them from
  my knowledge of Foundry on Windows and ran none of them there, since I tested
  on your Mac.

  1. Install Foundry (once)

  Foundry's installer (foundryup) is a bash script, so on Windows run it in Git
  Bash or WSL, not PowerShell:
  curl -L https://foundry.paradigm.xyz | bash
  foundryup
  Then check it from PowerShell:
  forge --version
  If forge isn't found, add Foundry to your PATH for this session:
  $env:Path += ";$HOME\.foundry\bin"

  2. Build and test
  cd path\to\ETHGlobal_Tech_Avinya\contracts
  forge install foundry-rs/forge-std --no-git   # first time only (needs git
  installed)
  forge build
  forge test
  forge test -vv                                # more detail on failures

  3. Deploy the factory to Hedera testnet

  Set the keys for this session only, and don't paste them into chat or commit
  them:
  $env:RELAYER_PRIVATE_KEY = "0x<relayer hex private key>"
  $env:HEDERA_RPC_URL = "https://testnet.hashio.io/api"

  forge create src/AgreementFactory.sol:AgreementFactory `
    --rpc-url $env:HEDERA_RPC_URL `
    --private-key $env:RELAYER_PRIVATE_KEY `
    --legacy --gas-limit 4000000 --broadcast `
    --constructor-args 0x2d879491dA59A0F5AA95ef719f3d3c679c08E37F
  The constructor argument is the verifier's address. You don't need to
  redeploy: the factory is already live at
  0x34a34Ad1FeB783FAF5B64249Ef2699a4cF9ff39D.

  4. Useful cast commands (reading the chain)
  # escrow address for an agreement id (bytes32)
  cast call 0x34a34Ad1FeB783FAF5B64249Ef2699a4cF9ff39D
  "escrowOf(bytes32)(address)" 0x<agreementIdBytes32> --rpc-url
  $env:HEDERA_RPC_URL

  # an account's balance (printed in weibar, divide by 1e18 for HBAR)
  cast balance 0x875fc8473b5507E78d60B52b171124a55e3129FC --rpc-url
  $env:HEDERA_RPC_URL

  # an escrow's state: 0 Created, 1 Funded, 2 Submitted, 3 Released, 4 Refunded
  cast call <escrowAddress> "state()(uint8)" --rpc-url $env:HEDERA_RPC_URL

  PowerShell uses a backtick ` for line continuation, where Mac and Linux use \.
  Always pass --legacy and a --gas-limit on Hedera. The relay's gas estimates
  are unreliable, and payouts to brand-new addresses need extra gas.
